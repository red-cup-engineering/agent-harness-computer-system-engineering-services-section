The original carrier now observes the actual session/model/effort before decoding its terminal report. It admits valid output through the original organizing Work codec. Invalid JSON or a refused native outcome becomes a ValidationFailure report carrying a SHA-256 reference to the original message, whose bytes remain in the original session artifacts. JSON parse failures do not copy raw output into diagnostics. The original session, task, prompt and usage evidence accompany the report. An actual completed session is never relabelled as an unstarted capacity refusal or restarted by this conversion.

The provider response constraint retains its object root and the original animating skill carrier while requiring output and a classical reading for native success, an error for native failure, and matching outer success/error fields. The organizing codec remains authoritative for semantic identity, JSON stability, output equality and codomain receiving. No malformed result becomes fulfilled Work. Historical admitted legacy reports retain their meaning. Independent receiving and parent fulfillment remain separate.

Six scoped receiving cases cover actual owner-generated successes/errors, invalid JSON, missing output, nonclassical readings, contradictory wrappers, mismatched output, schema rejection and legacy records. They do not claim a new model session or business acceptance. The selected native consumer also receives the existing upstream capacity-wait and explicit model/office prompt corrections from its original source owner.
