# Finish the requested work

Finish the authorized implementation, checks, installation, and receiving
consumer before treating a report or source commit as completion. A question,
discussion, or stop instruction does not require a commit.

Use [use-git](../use-git/SKILL.md) for the commit operation. Run it directly;
do not commission a special agent just to perform Git commands.

Select the literal files changed for this task, including both endpoints of
moves. Preserve unrelated work and pre-existing staged entries. Inspect the
selected changes and run the whitespace check on that cut. Use the existing
exact-path commit operator; do not reimplement temporary-index or staging
protocols in the session. A later concurrent change does not expand the cut.

For a package release, use the applicable publishing skill and verify the
installed consumer. For deployment, check the actual receiving service.
Source tests, registry publication, installation, deployment, and user
acceptance establish different results. Do not stop at an intermediate one
when the requested next step is authorized and available.

For a submodule, commit its owned change in that repository first. Update a
parent gitlink only when that update belongs to the authorized task; verify
that the referenced child commit is available to its receiver.

Report the result, relevant check, commit, and any material remaining gate.
Keep credentials and personal data out of Git and output. Persist a new
standing instruction only when the user actually gave one, at its existing
owner; use native continuity for ordinary task state. Do not create a new
journal, receipt, or plan solely to describe the session.
