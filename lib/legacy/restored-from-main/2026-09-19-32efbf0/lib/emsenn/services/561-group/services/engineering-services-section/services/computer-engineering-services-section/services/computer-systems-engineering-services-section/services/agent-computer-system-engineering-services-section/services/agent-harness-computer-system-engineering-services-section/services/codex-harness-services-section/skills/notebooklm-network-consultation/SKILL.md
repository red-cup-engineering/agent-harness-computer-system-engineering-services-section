# Disposable NotebookLM network consultation

Use the bundled command, not the fixed-corpus advisory adapter. It creates an ephemeral notebook from the matching repository files, buys one bounded data product, preserves its exchange receipt, and relies on the provider's exact-notebook cleanup receipt.

```sh
/home/emsenn/info/lib/emsenn/services/561-group/services/engineering-services-section/services/computer-engineering-services-section/services/computer-systems-engineering-services-section/services/agent-computer-system-engineering-services-section/services/agent-harness-computer-system-engineering-services-section/services/codex-harness-services-section/skills/notebooklm-network-consultation/scripts/consult-network-notebooklm.sh \
  "matching string" "Extract one row per asserted actor, with columns for actor, public face, claimed effect, evidence path, and uncertainty." --limit 300
```

The default product is a CSV data table. Ask for an explicit row model, fields, categories, provenance, uncertainty, and a falsifying next observation. Use `--artifact json --schema emsenn/schema/...` only when a seated consumer schema already exists. Use `--artifact code` when NotebookLM should propose a complete Python analysis instrument that parses named evidence and emits a specified JSON/CSV carrier; retain and independently assay that instrument for its analytical result, never as repository patch material. `--artifact report` is a last resort for prose synthesis, not a programming-advice mode.

To include one authorized session transcript, add `--session /absolute/path/to/transcript.jsonl`.

Read the returned exchange record and its `ephemeral_cleanup` field. An `artifact` outcome is evidence or a proposed transformation, not authority and not verified code. A `refusal` or leaked cleanup receipt is a real provider outcome, never a reason to fall back to an unpinned or persistent notebook.
