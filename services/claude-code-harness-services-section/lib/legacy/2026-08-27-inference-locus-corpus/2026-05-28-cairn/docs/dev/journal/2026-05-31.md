This entry records a rule for the claude-code-harness specification before that specification exists, so the requirement is filed in the right package and not lost.
The harness package currently carries journals but no `docs/dev/specification.md`; when the harness is rewritten as a proper catalog, the rule below belongs in that specification.

## The rule to carry forward

The harness specification should state that the directory the harness operates over — the *harnessed directory* — should have a `CLAUDE.md` at its catalog root.
In RFC-2119 terms once the specification is written, this is a SHOULD, not a MUST: a harnessed directory without a `CLAUDE.md` is not malformed, but the harness works best when the root carries one, because `CLAUDE.md` is the file the running Claude Code agent reads on entry — the bridge between the operating system's `claude-code` and whatever catalog it has been pointed at.

## Why this is a harness concern, not a TRC concern

The typed-resource-catalog specification has nothing to say about `CLAUDE.md`.
A TRC is a TRC whether or not any agent ever harnesses it; `CLAUDE.md` is meaningful only to the harness, which is the thing that reads it.
Putting this rule in TRC would leak a harness concern into the catalog substrate.
Keeping concerns inside the package whose concern they are is part of getting the wider cleanup right, so this rule stays here, with the harness.

## Status

Recorded only.
No specification file exists in this package yet to carry the rule normatively; writing that specification is part of the harness rewrite.
Until then, this entry is where the requirement lives.
