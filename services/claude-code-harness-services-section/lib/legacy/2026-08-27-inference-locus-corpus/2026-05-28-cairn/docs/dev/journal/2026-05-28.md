# claude-code-harness: a self-contained, categorically-correct choreography catalog

## Why this exists

emsenn wants Claude Code to be the top-level **choreography character** he talks to: one expensive conductor seat above a swarm of cheap, fungible inferring-enactors (Groq/Cerebras/NIM).
The conductor takes a user prompt and uses the repo's math to do good inference, take constrained actions, and settle outcomes.
Two hard constraints made the existing approaches unusable:

1. **Self-contained.** The prior sketch of Claude Code lived wedged deep inside `development/active/` and broke whenever the surrounding tree churned.
  This catalog is its own TRC root and reaches nothing outside itself.
2. **Categorically correct, from scratch.** The potential sketch was confirmed mis-arranged (its `claude-code.schema.json` was a bare `{"type":"object","properties":{"name":{"const":"claude-code"}}}` -- raw `type:object`, no derivation from articulating's primitives).
  Redone here, not migrated.

## Two load-bearing categorical corrections (emsenn, 2026-05-28)

1. **Every `$thing` is generated, so it is simultaneously a carrier object AND the subcategory it generates** -- and being a generated subcategory is *how it inherits the ambient machinery.* `claude-code`, generated under `aperiodic-articulation-category`, therefore does NOT re-implement FOUR, the cell partition, or the predicating->positing->settling descent: it **inherits** them.
  It is fractal -- `inferring`, `prompting`, etc. are each object-and-subcategory in turn.
  Placement IS inheritance; the directory tree does the mathematical work.
2. **Nothing is outside anything.** No "pre-illocutionary outside," no sidecar.
  Hooks, tools, session state, and the conductor's own memory all nest *inside* and settle *into* the `.jsonl` logs the proof engine checks.
  This is the strongest form of the memory fix: a drifting sidecar is structurally impossible because there is no outside for it to drift into.

## What was disowned (and why)

`trc-layout.json` / the "trc-layout probe/validator" are **not canonical** -- they appear only under `development/experimental/` and zero times in the handrolled SPOTCOMP spec.
The canonical self-containment + relocatability mechanism is TRC §3.4: a `package.json` at the catalog root with an `imports` map of `#schema/`/`#script/` aliases, deps imported by alias never by relative path.
This catalog uses exactly that.
`swarm-runtime` was treated as a peer experiment (a data point), not a template, because it is built atop that non-canonical tooling.

## The arrangement

- Base primitives `library/{void,token,claim,utterance}` -- the Chu-shape carrier.
- `articulating` generates `aperiodic-articulation-category`; the cell partition gives FOUR
  (potential/active/stable/absurd). The descent `predicating -> positing -> settling` lives inside
  the *potential* cell at each level, ending at `finite-settlement-cell` and the `eavt-row`.
- `claude-code` is the carrier-object-and-subcategory inside `aperiodic-articulation-category`
  (`$ref`s `aperiodic-articulation-cell` -- inheritance made type-level). It hosts:
  - `inferring : context -> inference` (root; the enactor is external and fungible),
  - `prompting : utterance -> user-prompt` (the human-enactor sibling),
  - `decoding : (handler-class, payload) -> utterance|rejection|obstruction` (hooks enter here),
  - `hacking/delegating : task -> subagent-settlement` (consensus = knowledge-order meet;
    disagreement = H^1 of the multi-observer sheaf),
  - `hacking/invoking : tool-call-envelope -> tool-result` (constrained actions).
- `conductor.mjs` runs the loop and dual-files EAVT rows about its own activity at the `session` log
  (subject anchor) and each morphism's log (predicate anchor), per §4.
